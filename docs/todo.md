## Lower priority / deliberate limitations (state these in the report)
- **Imputation limits**: single-value imputation only (median/mean/constant); no model-based or multiple imputation, and no test of whether values are missing at random.
- **Categorical (non-numeric) features are unsupported**; the loader refuses them with a specific error. Design notes for picking it up later are in `design.md` §3.8.
- No QC filtering of cells/features (row filtering would need label alignment across scripts; the mitochondrial filter is gene-name specific). Confirmed as a real gap by the live pbmc run (DATA_DESCRIPTION.md says the data are unfiltered).
- No marker-gene coloring or cell-type annotation (needs domain knowledge; the findings rules forbid naming cell types for unlabeled data).
- UMAP runs on the preprocessed matrix independently, not on a PCA neighbor graph as the Scanpy tutorial does.
- GPLVM is not implemented; the adversarial critic subagent and the synthetic-data generator are deferred.
- Dense-only pipeline: very large sparse datasets hit a clear size-limit error at load time.
- **Artifacts are keyed by method name only.** A second UMAP with a different seed/hyperparameter setting can't be stored alongside the first; the live pbmc run worked around this by adding t-SNE (a different method entirely) as its second visualization for the "two seeds or settings" guard rail, rather than a second UMAP run.
- **`cluster.py` and `run_log.json` keep only the current state, not history.** Rerunning clustering with a revised `k_range` overwrites `metrics/clustering.json`, so an earlier scan's numbers (e.g. the k=2 result that motivated the revision) aren't traceable afterward unless copied out by hand first. Likewise, once `run_plan.py` reuses a method's artifacts, `run_log.json` reports its status as "reused" indefinitely; the original run's "ok" status isn't kept. Both are consistent with the reuse-before-recompute design (rule 13) but mean the plan/findings text, not the JSON, is the place to record a revision's own reasoning.
- **No label-name mapping.** `DATA_DESCRIPTION.md`'s `## Loading` section has no key for an index-to-name lookup, so a dataset like pathmnist that documents 9 named tissue classes can still only be plotted and reported with the raw label integers (0-8).
- **`sparse_pca` has no variance-explained diagnostic.** Unlike `PCA`, sklearn's `SparsePCA` doesn't expose an `explained_variance_ratio_`-style number tied to its (non-orthogonal) components, so its metrics/report rows are blank in the "variance explained" and "PCs for 90%" columns; the report's metric definitions page says blank means "PCA only," so this is disclosed rather than hidden, but it does mean the required PCA variant can't be judged on that axis.
